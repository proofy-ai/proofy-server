# 화면 구성과 사용자 프로세스 (A-lite 웹앱)

> 청년 지급정지 소명 도우미 · 모바일 우선 웹앱
> 작성일 2026-11-21 · 마감 11/23(월) 17:00
> 관련 문서: `docs/contract.md`(API 계약 정본), `docs/agent-design.md`

## 📍 서비스 위치

지급정지된 계좌의 명의인이 은행에 이의제기할 때 서류를 직접 준비해야 한다. 우리 서비스는 증빙을 읽고 정리해서 소명서 초안과 부족한 서류 안내를 만든다. 접수와 심사는 은행이 하고, AI는 판정하지 않는다.

## ⚖️ 이의제기 절차와 서비스가 돕는 지점

1. **지급정지**
   - 내용: 은행 등이 계좌 전부를 지급정지하고 명의인에게 통지
   - 출처: 법 제4조(원문 확인)
   - 서비스 역할: 해당 없음
2. **채권소멸절차 공고**
   - 내용: 금감원이 공고하고 이의제기 방법·절차를 함께 알림
   - 출처: 법 제5조(원문 확인)
   - 서비스 역할: 공고일 입력으로 기한 계산
3. **이의제기** ← 서비스가 돕는 곳
   - 내용: 지급정지일부터 공고일 기준 2개월 전까지 은행에 제출. 서류는 이의제기신청서(별지 제4호), 사기이용계좌가 아니라는 증명자료, 신분증 사본
   - 출처: 법 제7조, 시행령 제7조(원문 확인)
   - 서비스 역할: 소명서 초안, 부족한 서류 안내
4. **심사**
   - 내용: 원칙 5영업일 이내. 보완이 필요하면 5영업일 연장, 재보완이면 3영업일 더 연장
   - 출처: [아시아경제 2026.5.3](https://view.asiae.co.kr/article/2026050306453019512)(기사 원문 확인, 금감원 원문 미확인)
   - 서비스 역할: 제출 후 흐름 안내
5. **결과**
   - 내용: 해제 또는 불수용. 피해자가 이의제기를 통보받은 날부터 2개월 전에는 해제하지 않지만, 객관적 자료로 충분히 소명하면 해제할 수 있음
   - 출처: 법 제8조 ②(원문 확인)
   - 서비스 역할: 불수용 시 법률 상담 안내(정적 문구)

소명 자료는 입금 경위 · 범죄에 가담하지 않았다는 설명 · 피해를 입은 경위로 나눌 수 있다([법률사무소 안내 글](https://www.yglaw.co.kr/bbs/board.php?bo_table=lawinfo&wr_id=27), 공식 자료 아님). 탭 C 초안은 이 세 묶음으로 나눠 쓴다(`docs/agent-design.md` 1절, 계약 `DraftSection`).

법 원문: [국가법령정보센터](https://www.law.go.kr/법령/전기통신금융사기피해방지및피해자산환급에관한특별법)

## 🧭 화면 흐름 (흐름 화면 6개 + 체험 계정 선택·내 사건)

```text
홈 ─┬→ L 체험 계정 선택 ──(test01·test02)──────┐
    │                                           ↓
    └→ 2 내 상황 ────────────────────────→ 3 사연·증빙 → 4 분석 중 → 5 결과 → 6 제출 가이드
M 내 사건(마이페이지) ── 이어서 하기 → 그 사건의 현재 단계 화면
```

L·M은 번호 대신 글자로 둔다. 1~6번 번호는 `docs/contract.md`와 맞춰 그대로 쓴다.

### L. 체험 계정 선택(로그인)
- **사용자가 하는 일:** 체험 계정 버튼을 하나 누르거나 "직접 해 보기"를 누른다. 아이디·비밀번호는 없다
- **보여 주는 것**
  - test01·test02 가상 프로필 카드(`docs/contract.md` 6절 체험 계정 표)
  - "버튼을 누를 때마다 나만의 체험 사건이 새로 만들어집니다" 안내
  - 누르면 서류가 채워진 3번 화면으로

### 1. 홈
- **사용자가 하는 일:** 시작하거나, **샘플로 체험하거나**, 내 사건으로 간다
- **보여 주는 것**
  - 소개, 절차 타임라인, 필요한 서류 요약
  - **"샘플로 체험하기"**(→ L), "이의제기 준비 시작"(→ 2)
  - "시연용 서비스이며 예시는 합성 데이터" 안내
  - 내 사건은 헤더 버튼으로 간다

### M. 내 사건(마이페이지)
- **사용자가 하는 일:** 이 브라우저에서 만든 사건을 이어서 하거나 지운다. 화면 설정(큰글씨·다크 모드)을 바꾼다
- **보여 주는 것**
  - 사건 카드(유형, D-day, 현재 단계, 체험 사건 표시, 이어서 하기, 지우기)
  - 사건이 없으면 빈 목록 안내
  - "24시간 뒤 자동 삭제" 안내
  - 화면 설정(FE 전용, 계약 6절)

### 2. 내 상황
- **사용자가 하는 일:** 지급정지 통지일, 공고일(모르면 건너뜀), 문제된 입금 유형(급여, 물품 거래, 모르는 입금), 입금액, 과거 지급정지 이력 여부를 입력한다
- **보여 주는 것:** 이의제기 **남은 기한 D-day**, 유형별 안내

### 3. 사연·증빙
- **사용자가 하는 일:** 거래 경위를 짧게 입력하고 유형별 체크리스트에 맞춰 사진을 올린다
- **보여 주는 것**
  - 유형별 서류 예시 체크리스트
  - 거래내역서에 **"AI 분석에 필요"** 배지(없으면 분석 시작 불가)
  - 업로드 영역 위에 **"실제 서류 대신 샘플(합성) 서류만 올려 주세요" + [샘플 서류 받기]**
  - 신분증은 받지 않고 "별도 첨부" 안내

### 4. 분석 중
- **사용자가 하는 일:** 기다린다
- **보여 주는 것**
  - 단계 표시: 글자 읽는 중 → 거래내역과 대조 중 → 초안 작성 중(문구는 서버 `stages[].label`)
  - 아래에 `steps` 마지막 몇 줄(AI가 밝힌 조회 이유, 어긋남 발견, 스스로 고친 문장)을 한 줄씩

### 5. 결과
- **사용자가 하는 일:** 탭 3개를 확인하고 초안을 수정한다
- **보여 주는 것**
  - **탭 A 증빙 대응표:** 주장, 증빙, 거래내역 연결과 어긋나는 부분 경고
  - **탭 B 부족한 서류:** 체크리스트
  - **탭 C 소명서 초안**
    - 입금 경위 · 가담하지 않았다는 설명 · 피해 경위 묶음 제목(`section`)
    - 편집 가능
    - 증빙 없거나 **자료와 어긋난** 내용은 "확인 필요" 표시
    - 문장마다 "직접 확인했어요" 체크
  - 상단에 D-day 고정
  - **탭 위에 AI 의견·질문 카드(v0.8 제안)**
    - 에이전트가 법령·서류를 근거로 낸 조건부 의견(근거 조항 인용, 결과 예측은 안 함)
    - 부족한 사실을 묻는 질문 0~3개, 답 입력칸
    - "답하고 다시 분석": 4번으로 가서 답을 반영해 다시 분석, 필요하면 또 질문
  - **상담 안내:** 사연에 통장 대여·송금 대행으로 읽히는 표현이 있으면
    - 탭 대신 "법률 상담을 먼저 받으세요" 카드(걸린 표현, 대한법률구조공단 132, 금융감독원 1332)와 그 아래 AI 의견·질문 카드를 보여 주고 6번으로 가지 않는다
    - 질문에 답해 다시 분석하면 상담 안내가 풀릴 수 있다

### 6. 제출 가이드
- **사용자가 하는 일:** 최종 점검 후 초안을 복사하거나 저장한다
- **보여 주는 것**
  - 이의제기 5단계 중 지금 위치(자료 준비 끝 → 다음은 은행 제출)
  - 낼 서류 3종, 은행에 직접 제출
  - 제출 후 흐름(심사 5영업일, 보완 요구 시 기한 안에 재제출)
  - 받아들여지지 않으면 법률 상담(대한법률구조공단 132)
  - 거짓 이의제기 처벌 경고
  - **확인하지 않은 문장이 남아 있으면 복사·저장 전에 확인창**

### 화면 3의 유형별 서류 예시

출처에서 확인한 세 유형만 쓴다.

- **급여 입금**
  - 제출 서류: 급여 입금내역 + 건강보험자격득실확인서 또는 재직증명서 중 하나
  - 출처: [한국일보 2026.5.3](https://www.hankookilbo.com/news/article/A2026050313580002729)
- **물품 거래 대금**
  - 제출 서류: 사업자등록, 거래상대방과의 대화내역 + 계약서, 세금계산서, 거래명세서 중 하나
  - 출처: 같은 기사
- **모르는 입금(통장 묶기)**
  - 제출 서류: 협박 문자 등 피해금 편취 의도가 없음을 보여 주는 객관적 자료
  - 출처: [금융위원회 보도참고 2024.2.1](https://www.fsc.go.kr/no010101/81640)(원문 확인), [머니투데이 2025.12.1](https://www.mt.co.kr/society/2025/12/01/2025120111431762125)(원문 확인: "협박 메시지 등 객관적 자료가 없으면 이의제기가 수용되기 어렵다")

모르는 입금 유형은 공식 서류 목록을 찾지 못했다. 협박 문자 외의 자료(은행·경찰 신고 내역 등)는 AI 권장 자료로만 보여 준다.

위 목록은 출처 근거의 제출 서류다. 이와 별도로 **문제된 입금이 보이는 거래내역서**는 AI가 사연과 대조하는 데 필요해서 세 유형 모두 분석 시작 조건으로 둔다(급여 유형은 "급여 입금내역"이 같은 서류). 법령·기사상 의무 서류로 표시하지 않고 "AI 분석에 필요" 배지로 구분한다(물품 거래·모르는 입금은 `ANALYSIS_INPUT` 묶음). 근거: `docs/contract.md` 4.2, 4.9.

물품 거래 유형의 서류 기준(사업자등록 등)은 사업자를 전제로 하므로, 안내와 시연은 **청년 1인 온라인 판매 사업자**의 판매 대금으로 한다. 개인 간 중고거래는 서류 기준을 확인하지 못해 다루지 않는다.

### 🧪 체험 계정 (심사자용)

심사위원은 합성 서류 없이 처음부터 입력할 수 없으므로, L 화면에서 체험 계정 버튼을 누르면 합성 서류가 들어간 사건이 바로 만들어진다(`POST /cases/sample`). 3번 화면에서 바로 "분석 시작"을 누르면 4~6번을 모두 볼 수 있다.

- **"로그인"은 시나리오를 고르는 버튼이다.** 서버 인증은 없다. 버튼을 누를 때마다 그 사람만의 사건이 새로 생겨서 여러 심사위원이 같은 계정을 눌러도 분석·초안이 섞이지 않는다. 공용 계정을 진짜로 만들면 동시 분석 충돌, 초안 덮어쓰기, 서버 인증 신규 개발이 생겨서 하지 않는다.
- 대회 제9조(로그아웃 상태에서 접근·실행)를 그대로 만족한다. 이름·연락처는 받지 않고 가상 프로필만 보여 준다.

**test01 · 물품 거래**
- 시나리오: 청년 1인 온라인 판매 사업자. 물건값으로 받은 돈이 보이스피싱 피해금
- 고른 이유: 보도에 가장 자주 나오는 유형("물건 팔고 받은 대금 때문에 계좌 정지", [MBC 2024](https://imnews.imbc.com/replay/2024/nwdesk/article/6584366_36515.html)), 서류 기준이 있음
- 보여 주는 것
  - 대화 속 합의 금액(12만 원)과 입금액(15만 원) 불일치 → 탭 A 경고, 탭 C "확인 필요"
  - 거래명세서 없음 → 탭 B

**test02 · 모르는 입금(통장 묶기)**
- 시나리오: 모르는 사람이 10만 원을 보낸 뒤 허위 신고, "20만 원 보내면 신고 취하해 줄게" 문자
- 고른 이유: 2025년부터 늘어난 신종 수법, 24세 사회초년생 사례 보도(머니투데이 2025.12.1), 법 개정 근거(협박 문자)와 바로 이어짐
- 보여 주는 것
  - 입금액 일치, 받은 돈이 빠져나가지 않았음을 거래내역에서 확인
  - 사연의 입금 날짜와 거래내역 날짜 불일치 → 탭 A 경고
  - "바로 은행에 알렸다"는 진술만 있음 → 탭 B AI 권장

참고

- 급여 시나리오는 서류 기준은 있지만 흔하다는 근거를 찾지 못해 체험 계정에서 뺐다. 샘플 데이터는 시간이 남으면 만든다(P1).
- 유형별 비율 통계는 찾지 못했다. "가장 자주 나온다"는 보도 빈도 기준이다.
- 샘플 사건에서 AI 호출이 실패하거나 하루 한도를 넘으면 미리 만든 결과로 끝내고, 결과 화면에 "미리 만든 샘플 결과"라고 표시한다(`docs/contract.md` 4.10). 심사 중 오류로 시연이 멈추지 않게 하려는 것이다.

### 🏠 홈 화면 구성

- **상단:** "내 계좌가 지급정지됐나요?"와 **이의제기 준비 시작** 버튼
- **내 사건 버튼:** 헤더 오른쪽에 항상 보인다(M 화면 제외, → M). 진행 중인 건 카드는 M 화면이 대신한다
- **절차 한눈에:** 지급정지 → 채권소멸 공고 → 이의제기(공고일 기준 2개월 이내) → 심사(원칙 5영업일) → 결과, 현재 위치 표시
- **필요한 서류 요약:** 이의제기신청서, 소명자료, 신분증 사본
- **안내:** AI는 판정하지 않고 서류 준비만 돕는다는 문구, 거짓 이의제기 처벌 안내

## 💛 사용자 친화 원칙

- 한 화면에 질문 하나, 상단 진행 표시줄, 쉬운 말(법률 용어는 괄호로 설명)
- 기한 배지(D-day)를 2번 화면부터 계속 보여준다. 이 서비스에서 가장 급한 정보다.
- AI가 못 읽은 서류와 모순은 숨기지 않고 "직접 확인" 항목으로 보여준다.
- 서버 로그인은 없다. L 화면의 체험 계정은 시나리오 버튼이다. 사건은 브라우저 저장(localStorage)에 최대 10건 두고 M 화면에서 본다.
- 하단 탭바는 두지 않는다. 흐름이 한 방향이라 홈 버튼 하나로 충분하다.

## 📐 범위 결정

- **입력할 수 있는 유형은 급여, 물품 거래(1인 판매 사업자), 모르는 입금(통장 묶기) 세 가지다.** 출처로 서류 예시를 확인한 유형이 이 셋뿐이다. 개인 중고거래는 금감원 기준의 사업자등록증이 없어 다루지 않는다.
- **체험 계정(시연)은 test01 물품 거래, test02 통장 묶기 두 가지다.**
- **필수 화면은 L(체험 계정 선택)과 2~6번이다.** L은 심사자가 체험할 입구라서 빼지 않는다. 홈의 나머지는 마지막에 만들어도 된다.
- **시간이 부족하면 뺀다:** M 내 사건, 6번의 PDF 저장, 급여 샘플 데이터
- **통장 대여·양도, 환전·구매대행·송금 알바는 다루지 않는다.** 이의제기보다 처벌 위험이 먼저인 사안이라 소명서를 쓰지 않고 상담 안내를 띄운다. v0.8 제안부터는 에이전트가 문맥을 읽어 판단하고("빌려준 적 없다"는 걸지 않음), 사용자가 질문에 답해 상황을 설명하면 다시 판단한다.
- **소액 특례 안내는 P0에서 뺀다.** 기준 금액과 이력 기간을 확인하지 못해 계산할 수 없다.
- **시연은 합성 데이터만 쓴다.** 홈과 3번 화면에 안내를 둔다(해커톤 AI 활용 기준 제7조).
- **알림(푸시, 문자)은 이번 범위가 아니다.** 결과 화면에 기한 안내 문구와 D-day 표시만 넣고, 알림은 확장 가능성 항목에 적는다.
