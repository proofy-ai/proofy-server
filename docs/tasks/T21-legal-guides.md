# T21 내 상황 정리 + 법령 근거

- 단계: 3단계 앞(11/22 결정, 실제 AI 전에 2시간 안에서 끊는다) · 상태: **보류**(11/22, #47: 계약을 v0.6.5로 되돌림. 코드는 남김) · 이슈: #43 · PR: #44

## 왜

청년 입장에서는 ① 내 상태를 설명해 지급정지가 어떻게 된 상황인지 파악 → ② 관련 법 조항을 먼저 따져 봄 → ③ 그에 맞게 대응(서류·소명)하는 순서가 맞다(11/22 사용자 지적). 지금 흐름은 법 안내가 6번(제출 가이드)에만 붙어 있어 "왜 이 서류를 내는지" 모른 채 서류부터 올리게 된다.

조문 원문을 레포에 저장해 두고 쉬운 설명의 원문 발췌를 원문과 대조하면, 뒤의 c 단계에서 AI가 조항을 고를 때도 같은 원문·목록으로 검증할 수 있다.

## 범위

- 새 화면 **2A 내 상황 정리**(2번 다음, 3번 앞). 화면 번호는 그대로 두고 사이에 끼운다(FE가 쓰는 번호가 바뀌지 않게)
- 입금 유형별 쉬운 설명을 서버 상수로 두고 `GET /legal-guides?inflowType=`로 내려준다(계약 v0.7, 추가만)
- 원문 스냅샷: `docs/legal/`(11/22 받음, 커밋됨)
- 문서: `docs/screen-flow.md` 흐름·절차 표, `docs/contract.md` 3절 화면별 호출·4.2.1·변경 이력

## 제외

- AI가 사연을 보고 조항을 고르는 것(c 단계, b 다음)
- 사연 입력을 2번 화면으로 옮기는 것(c를 할 때 다시 정한다, 아래 "정할 것" 3)
- 체크리스트 항목에 "어느 사유를 보여 주는 자료인지" 필드를 붙이는 것(시간이 남으면 4.2에 추가)
- 은행별 절차 안내(공식 자료 없음)

- **판정하지 않는다:** "당신은 2호에 해당"이 아니라 "물건값·급여라면 보통 이 사유로 이의제기합니다". 응답에 고정 `disclaimer`("해당 여부는 은행이 판단합니다")를 넣는다

## 구현 계획

### API `GET /legal-guides?inflowType=GOODS` (인증 없음, 사건 없이도 부름)

```json
{
  "inflowType": "GOODS",
  "disclaimer": "이 안내는 법 조항을 쉽게 옮긴 것입니다. 내 경우가 해당하는지는 은행이 판단합니다.",
  "items": [
    {
      "code": "REASON_2",
      "stage": "SITUATION",
      "title": "사유 2. 정당하게 받은 돈",
      "commonForType": true,
      "plain": "…쉬운 말…",
      "quote": "…원문 발췌(스냅샷 그대로)…",
      "sourceRef": { "label": "통신사기피해환급법 제7조제1항제2호", "url": "https://www.law.go.kr/…" },
      "effectiveDate": "2026-10-02"
    }
  ]
}
```

- `stage`: `SITUATION`(2A 화면) · `SUBMIT`(6번 화면). FE는 화면마다 해당 `stage`만 순서대로 보여 준다
- `inflowType`이 `OTHER`면 공통 항목만. 잘못된 값은 `400 VALIDATION_ERROR`(4.2와 같은 규칙)

### 쉬운 설명 목록(초안, 문구는 구현 때 다듬음)

이의제기 사유 세 가지(법 제7조①1~3호)는 **입금 유형과 상관없이 모두** 보여 주고, 그 유형에서 보통 쓰는 사유에만 `commonForType: true`를 붙인다(11/22 방법 2). 나중에 AI가 다른 사유를 짚어도 2A에서 이미 본 내용이라 어긋나 보이지 않게 하려는 것이다.

| code | stage | 쉬운 말 | 근거(quote) | 대상 · `commonForType` |
|---|---|---|---|---|
| `WHAT_HAPPENED` | SITUATION | 사기 피해금이 들어왔다는 신고 등으로 은행이 계좌 전체의 돈을 못 빼게 막았습니다(지급정지). 내 이름의 전자금융거래가 제한될 수도 있습니다 | 법 4① | 전체 |
| `DEADLINE` | SITUATION | 기한은 통지받은 날이 아니라 금융감독원 공고일부터 2개월입니다. 지나면 묶인 돈에 대한 권리가 사라집니다 | 법 7① 본문, 9① | 전체 |
| `REASON_1` | SITUATION | 사유 1. 이 계좌가 사기에 쓰인 계좌가 아니라는 것을 설명 | 법 7①1 | 전체 · 없음 |
| `REASON_2` | SITUATION | 사유 2. 물건·서비스의 대가나 급여처럼 정당하게 받은 돈임을 객관적 자료로 보여 줌. 사기에 쓰이는 줄 알았거나 크게 부주의했다면 인정되지 않음 | 법 7①2 | 전체 · SALARY·GOODS |
| `REASON_3` | SITUATION | 사유 3. 이 계좌가 피해자의 돈을 빼돌리는 데 쓰이지 않았음을 객관적 자료로 보여 줌. 인정되면 피해금을 뺀 나머지가 풀림 | 법 7①3, 8①2 단서 | 전체 · UNEXPECTED |
| `HOLD_TWO_MONTHS` | SITUATION | 이의제기를 해도 피해자가 통보받은 날부터 2개월 동안은 묶여 있을 수 있음. 자료로 충분히 보여 주면 그 전에 풀릴 수도 있음 | 법 8②2 | 전체 |
| `DONT_PAY_THREAT` | SITUATION | 피해자가 신청을 모두 취소하면 풀리는 것은 맞지만, "돈을 보내면 취소해 주겠다"는 연락에 응해 돈을 보내지 말고 은행·경찰(112)에 알리세요 | 시행령 8①1 | UNEXPECTED |
| `HOW_TO_SUBMIT` | SUBMIT | 계좌가 있는 은행에 이의제기신청서 + 사기에 쓰인 계좌가 아니라는 증명 자료 + 신분증 사본 | 시행령 7 | 전체 |
| `REASON_FIELD` | SUBMIT | 신청서 "이의제기 사유" 칸은 구체적으로 적어야 함. Proofy 초안을 이 칸에 옮겨 적을 수 있음 | 별지 4 | 전체 |

- `quote`는 원문 그대로 발췌한다. 떨어진 두 곳을 인용할 때는 ` … `로 잇는다(테스트는 조각마다 원문에 있는지 본다)
- 2A 화면 아래에 "내 경우와 다르면 입금 유형 다시 고르기 → 2번" 버튼(FE)
