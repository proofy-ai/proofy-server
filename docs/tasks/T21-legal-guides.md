- **바뀐 흐름(제안, 사용자 확인 전):**

| 순서 | 내용 | 화면 | 누가 |
|---|---|---|---|
| ① 내 상태 설명 | 통지일·공고일·입금 유형·금액 | 2번(그대로) | 사용자 |
| ② **내 상황 정리(새 화면)** | 무슨 일이 일어났나(피해구제 신청 → 지급정지 + 전자금융거래 제한) · 기한(공고일 기준 2개월) · 쓸 수 있는 이의제기 사유(물품·급여 = 법 제7조①2호, 모르는 입금 = ①3호, 인정되면 피해자산 뺀 나머지만 해제) · 보여 줘야 할 것(객관적 자료, 알았거나 중대한 과실이면 제외, 협박범에게 돈 보내지 말 것) | 2번 다음 | 코드(지금) → AI(c) |
| ③ 대응 준비 | 그 사유를 보여 줄 서류·사연. 체크리스트에 "어느 사유를 보여 주는 자료인지" 연결 | 3번 | 사용자 |
| ④ 맞는지 확인 | 사연–서류 대조, 빠진 서류 | 4·5번 | AI + 코드 |
| ⑤ 제출 | 신청서 사유 칸에 초안, 은행 제출, 이의제기해도 2개월 유지될 수 있음 | 6번 | 코드 |

- **판정하지 않는다:** ②는 "당신은 2호에 해당"이 아니라 "물건값이라면 보통 이 사유로 이의제기합니다 · 해당 여부는 은행이 판단"
- **FE 부담 최소화:** 새 API 없이 입금 유형별 **고정 문구를 계약 문서에** 넣고 FE가 붙여 넣는 방식을 추천했다(FE와의 합의 방식 = 계약이 기준, 추가만). 사용자 최종 확인은 아직
- **AI 역할(사용자 질문 "AI 역할이 너무 적지 않나"에 대한 답):** 앞부분이 전부 코드면 사용자가 처음 만나는 단계에 AI가 안 보인다. 입금 유형 3개로는 현실(개인 중고거래, 지인 대신 받은 돈, 프리랜서 대금)을 다 못 나누므로, c에서 **AI가 사연을 읽고 저장한 조항 목록 안에서만 관련 조항을 고르고 근거 문장을 냄** → 코드가 조항 코드(목록 안 값)·사연 인용(원문 대조)을 검증. 이렇게 하면 법 → 서류 → 대조 → 초안 전 구간에 AI가 들어간다(RAG). 걸리는 점: 사연을 3번이 아니라 2번에서 받아야 함(FE 화면 순서 변경)
- **추천 순서:** T21에서 ② 상황 정리를 코드 규칙으로 → b 실제 Claude → c에서 같은 화면을 AI가 고르도록. c를 못 끝내도 코드 버전이 남는다
- **T21에서 할지:** 화면 흐름·계약이 바뀌므로 문서(screen-flow, 계약)를 먼저 고치고, 작업은 T21 이름을 넓혀 그대로 한다(새 작업으로 떼면 이슈·PR만 늘어남)

## 왜

청년이 법 조문을 직접 찾아 읽지 않아도 기한·제출 서류·이의제기 사유·주의할 점을 쉬운 말로 이해하게 한다. 조문 원문을 서버에 저장해 두면, 나중에 AI가 조문을 인용할 때 코드가 원문과 대조할 수 있다(이후 "조문 요구 ↔ 준비 상태" 비교의 바탕, 11/22 a→b→c 순서의 a).

## 범위

- 국가법령정보센터 현행 원문 확인(11/22): 법 [시행 2026. 10. 2.] 법률 제22047호, 시행령 [시행 2026. 10. 1.] 대통령령 제36729호, 별지 제4호서식 이의제기신청서(2026. 9. 29. 개정)
- 원문 스냅샷을 레포에 저장(법령은 저작권 보호 대상이 아님, 저작권법 제7조)
- 쉬운 설명 목록(코드 상수): 항목마다 쉬운 말 + 원문 발췌 + 출처(조항·링크·시행일) + 해당 입금 유형
- `GET /legal-guides?inflowType=…` 추가(계약 v0.7, 추가만)
- 기존 문서·출처 정리: `docs/screen-flow.md` 절차 표, 계약 4.2 출처 라벨
