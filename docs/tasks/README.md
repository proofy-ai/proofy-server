## 전체 흐름

```text
T00 규칙
```

가짜 분석을 먼저 만드는 이유
- FE가 AI 완성을 기다리지 않고 전 화면을 붙일 수 있다
- AI 연결이 늦어져도 시연 가능한 상태를 먼저 확보한다

**단계는 묶음이고, 실제 진행은 아래 "진행 순서"를 따른다.** 결과 응답 모양이 정해지는 T08 직후에 실제 AI 경로(T12~T16)를 먼저 이어 붙여, 11/22 낮에 Claude 분석이 한 번은 돌게 한다(11/21 결정). 가짜 분석만 있는 상태로 제출하면 "실제 AI 에이전트"라고 소개할 수 없기 때문이다.

## 작업 단위 원칙

- 작업 하나 = 이슈 하나 = 브랜치 하나 = PR 하나. 1~2시간 안에 끝나는 크기로 나눈다
- 순서: 이슈 생성 → 브랜치 생성 → 구현 계획 확인 → 구현 → 커밋 → 푸시 → PR (`CLAUDE.md` 작업 순서)
- 작업 파일(`T00-….md`)이 정본이다. 이슈는 짧게 쓰고 작업 파일을 가리킨다. 이슈 제목 앞에 `[T01]`처럼 작업 번호를 붙인다(작업 번호와 이슈 번호는 다를 수 있다)
- 작업 파일은 처음에 범위·제외·완료 조건만 적고, 진행하면서 구현 계획 → 결정 → 결과를 채운다
- 이슈 번호 = 작업 번호 + 2 (T01 = #3, T19 = #21). T20은 #25(예외). 레포 기본 브랜치는 `dev`라서(11/21 변경) `dev`로 머지하면 `Closes #n`이 이슈를 닫는다
- 마일스톤: 단계별 4개(1단계 사건·증빙 ~ 4단계 배포·마무리)
